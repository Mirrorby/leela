# Tribute: разовые покупки Лилы

Интеграция принимает подтверждённые покупки Tribute и начисляет доступ
на существующий баланс Telegram-пользователя. Stars продолжают работать.
Ключ и настройки Tribute хранятся на сервере. Пока они не добавлены,
`POST /tribute/webhook` отвечает `503`, без изменения балансов.

## Что подключено

| Товар Лилы | `productId` | Начисление |
|---|---|---|
| 1 партия | `game_1` | 1 партия |
| 5 партий | `game_5` | 5 партий |
| ИИ-разбор | `ai_review_1` | 1 разбор |
| Партия + ИИ-разбор | `game_ai_combo` | 1 партия и 1 разбор |

Безлимитная подписка с автопродлением пока остаётся в Stars.
Подписки на каналы Tribute, донаты и физические товары не начисляют доступ.
Кнопка оплаты картой внутри Telegram Mini App не добавлена: цифровые покупки
внутри Telegram должны использовать Stars. Для карт используйте веб-ссылку
Tribute, распространяемую вне Telegram (например, на сайте).

## 1. Создайте один товар для первого теста

В [@tribute](https://t.me/tribute) откройте панель автора → «Цифровые товары» →
«Создать готовый товар». Пройдите необходимые шаги регистрации и верификации
автора. Начните с «Лила — 1 партия», затем добавьте остальные товары.

Сообщение, которое покупатель получит после оплаты, должно объяснять:

> Спасибо за покупку! Партия будет начислена на ваш аккаунт Лилы автоматически.
> Вернитесь в бот Лилы и откройте приложение. Используйте тот же Telegram-аккаунт,
> с которым оформляли покупку. Если баланс не обновился, обратитесь в поддержку.

Подставьте в сообщение реальную ссылку на бот Лилы и контакт поддержки.
Название, описание и цену задайте в Tribute. Сохраните товар и дождитесь
одобрения. В разделе товара «Ссылки» скопируйте **веб-ссылку** для оплаты картой.
Покупатель должен авторизоваться через Telegram: при покупке только через
электронную почту уведомление может не содержать Telegram ID, и автоматическое
начисление тогда невозможно. Проверьте этот сценарий до публикации ссылки.

## 2. Добавьте таблицу в D1

Перед запуском нового обработчика выполните только SQL из
`worker/migrations/0013_create_tribute_purchases.sql` в Cloudflare Dashboard →
D1 → база `leela` → Console. Оба оператора можно безопасно выполнять повторно.
Старые таблицы и балансы не изменяются.

Если существующие миграции уже отслеживаются Wrangler, вместо Console можно
применить миграции обычным для проекта способом. Не запускайте весь каталог
старых миграций впервые на рабочей базе без проверки состояния миграций:
в нём есть `ALTER TABLE`, которые не рассчитаны на повторное выполнение.

## 3. Добавьте две настройки Worker

Cloudflare → Workers & Pages → `leela-worker` → Settings → Variables and Secrets:

* **`TRIBUTE_API_KEY`**, тип Secret/Encrypt. Возьмите ключ в Tribute:
  панель автора → ⋯ → «Настройки» → «API-ключи» → создать ключ.
  Не отправляйте ключ в чат, не добавляйте его в GitHub или фронтенд.
* **`TRIBUTE_PRODUCTS`**, текстовая переменная с JSON. Ключи — реальные
  числовые ID товаров Tribute. Значения задают SKU Лилы и ожидаемую оплату.

Первый товар уже создан и указан в `worker/wrangler.toml`:

| Товар | Tribute ID | Веб-ссылка | Цена |
|---|---|---|---|
| Лила — 1 партия | `161238` | https://web.tribute.tg/p/FWC | $1.59 USD |

```json
{
  "161238": { "productId": "game_1", "amount": 159, "currency": "USD" }
}
```

Можно добавить только один товар. Суммы — копейки для RUB, центы для EUR/USD,
целые Stars для XTR. `159` USD означает $1.59. Цена и валюта должны совпадать
с фактически присылаемыми Tribute `amount` и `currency`; альтернативный способ
оплаты с другой валютой без соответствующей настройки отклоняется. Для начала
проверяйте именно веб-оплату картой, без скидок/промокодов.
При изменении цены сначала обновляйте ожидаемую сумму, затем проверяйте покупку.
При смене состава пакета создайте новый товар Tribute с новым ID.

Настройка первого товара уже сохранена в секции `[vars]` `worker/wrangler.toml`,
чтобы дальнейшие деплои имели ту же конфигурацию. Для новых товаров добавьте
их реальные числовые ID и проверенные цены. `TRIBUTE_API_KEY` всегда остаётся
Secret.

## 4. Укажите URL вебхука

В настройках API Tribute сохраните:

```text
https://<действующий-домен-leela-worker>/tribute/webhook
```

Используйте фактический адрес текущего Worker, заменив плейсхолдер.
Это отдельный маршрут: URL Telegram-вебхука не меняется.

## 5. Проверьте покупку

1. Запишите баланс партий нужного Telegram-аккаунта.
2. Откройте веб-ссылку Tribute в обычном браузере, войдите через тот же Telegram
   и оплатите тестовый товар реальной картой по установленной цене.
3. Заново откройте Лилу. Убедитесь, что купленный пакет добавился к балансу.
4. В D1 проверьте запись:

```sql
SELECT purchase_id, telegram_id, product_id, amount, currency, status,
       granted_games, granted_ai_reviews
FROM tribute_purchases ORDER BY created_at DESC LIMIT 10;
```

5. Проверьте отказ/отмену оплаты: пакет не должен начисляться.
6. Для проверки возврата согласуйте его с поддержкой Tribute и убедитесь,
   что webhook `digital_product_refunded` переводит запись в `refunded`.

Это тест с реальным платежом; интеграция в PR сама деньги не списывает.
Тестовое уведомление без `purchase_id` не подходит: нужен актуальный формат API.

## Поведение при сбоях и ограничения

* Подпись `trbt-signature` проверяется через HMAC-SHA256 по исходным байтам тела
  запроса. Telegram ID берётся только из подтверждённого уведомления Tribute.
* Запись покупки и начисление выполняются в одной D1-транзакции. При сбое
  обработчик возвращает `500`, позволяя Tribute повторить доставку.
* `purchase_id` защищает от повторных начислений, включая параллельную доставку.
* У каждой покупки сохраняются цена, валюта и начисления. Возврат использует
  сохранённые значения, даже если товар удалён из текущих настроек.
* Возврат, пришедший раньше покупки, сохраняется и блокирует позднее начисление.
* При возврате из текущего общего платного баланса вычитается размер пакета,
  с нижней границей 0. Уже сыгранные партии/готовые разборы не удаляются,
  бесплатный баланс не меняется. Если покупатель уже потратил пакет и имеет
  другие покупки, распределение возврата по ним проверяется вручную.
* Без `telegram_user_id` ответ `422`: нужно связать покупателя с Telegram через
  поддержку. Не используйте username или произвольно введённый ID для начисления.
* Несовпадение цены/валюты или данных уже известной покупки даёт `409`.
  Проверьте конфигурацию и повторную доставку. После завершения окна повторов
  Tribute потребуется ручная сверка с поддержкой.
* Статический тест API и локальные тесты не заменяют проверку реальной карты,
  доступности выплат для вашего профиля и доставки уведомления на production.
