# ИИ-разборы: резервирование и восстановление

Начало разбора и списание одного кредита выполняются в одном D1 batch. Краткий разбор (`kind: short`) использует только бесплатный счётчик; полный (`kind: full`) — только купленные кредиты. Бесплатный краткий разбор не заменяет оплату полного. Повторный запрос к pending или уже готовой запрошенной версии не списывает новый кредит. При переходе с краткой версии на полную резервируется платный кредит; краткий результат остаётся доступен. Неудачный INSERT или списание откатывает весь batch.

Поле `ai_reviews.updated_at` у pending хранит неизменный идентификатор попытки: время её резервирования. При повторе после failed оно строго увеличивается, даже если часы вернулись назад или два запуска произошли в одну миллисекунду. Только pending с этим идентификатором может получить результат или возврат. Не обновляйте это поле для прогресса/heartbeat без пересмотра протокола.

При ошибке статус failed и возврат в исходный счётчик free/paid фиксируются одной транзакцией. Повторный callback или восстановление не возвращают кредит ещё раз. Сбой аналитики не меняет результат и баланс. В пользовательское поле error записывается понятное сообщение, без тела ошибки Gemini.

Сроки:

- Запрос Gemini, включая чтение тела: 20 секунд.
- Резервирование pending: 60 секунд. Просроченный результат не принимается.
- GET статуса и POST запуска восстанавливают просроченный pending и возвращают кредит.
- Существующий cron каждые 5 минут также восстанавливает до 20 просроченных попыток за запуск, даже если пользователь закрыл игру.
- Клиентские запросы статуса/запуска: 15 секунд; общее ожидание результата: 90 секунд. Проверки идут последовательно, без наложения запросов.

Генерация остаётся короткой задачей через `waitUntil`. Если runtime прекратит работу до записи результата или возврата, резервирование восстановится при следующем чтении/запуске либо по cron. Генерация сама автоматически не повторяется: пользователь может запустить новую попытку после возврата. Для генераций длительнее текущего таймаута потребуется отдельная очередь фоновых задач.

Изменений схемы и новых секретов нет. Старые pending совместимы с восстановлением; уже готовые разборы сохраняются. Кредиты, потерянные старым кодом без записи ai_reviews, нельзя определить автоматически по этой таблице — для них нужна отдельная сверка.

Проверки включают SQLite с настоящими миграциями, rollback при ошибках INSERT/debit/refund, параллельные запросы, однократный возврат, поздние callbacks, восстановление pending, отказ аналитики и жизненный цикл ожидания на клиенте. Дополнительно сценарий проверен в локальном Miniflare/workerd с D1 и тестовым провайдером; реальный Gemini в этих проверках не вызывается.

## Запрос, язык и ограничения провайдера

`POST /api/v1/games/:id/analysis/start` принимает `kind: short | full` и необязательный `language: ru | en`. Без тела старый клиент получает краткую русскую версию; в непустом теле нужен корректный `kind`. Генерация доступна только для `FINISHED`/`ARCHIVED` и возвращает 202 при новом резервировании. Уже готовая запрошенная версия возвращается с 200, активная генерация — 409, недостаточный баланс — 402.

Язык сохраняется отдельно для краткой и полной версии в JSON разбора. Смена языка интерфейса не переводит готовый результат и не списывает ещё один кредит. Ответ статуса содержит `status`, `kind`, `content`, `shortContent`, `language` и `shortLanguage`.

Провайдер — Gemini, модель задана в `src/ai/geminiClient.ts` (`gemini-2.5-flash`), ключ — Worker Secret `GEMINI_API_KEY`. В промпт передаются намерение и путь игрока; для пути длиннее 120 ходов — первые 30 и последние 90, с точными агрегатами всего пути и отметкой пропущенной середины. Промпт ограничен 32000 символами до списания. Бюджет ответа: 768 токенов для краткого и 4096 для полного, бюджет размышления 0/1024 соответственно. Чтение ответа ограничено 128 КиБ. Ошибка, превышение размера или обрыв обрабатываются тем же механизмом возврата.
